# 决策捕获

> 在 **判断"这条要不要记"** 时按需加载。
> v1 的 L1/L2/L3 三级已废弃 —— 分级边界太模糊，模型必然误判。v2 只分两类：**决策** 与 **改动**。

## 一、核心洞察：物理大小 ≠ 决策重要性

| 修改 | 物理大小 | 重要性 | 记什么 |
|---|---|---|---|
| 改个错别字 | 小 | 低 | 改动（可完全不记） |
| 重写整章润色 | **大** | 低（没改方向） | 改动 |
| "攻防比 1.5 → 2.0" | **极小** | **极高** | **决策** |
| "这个系统砍了不做了" | 极小 | 极高 | **决策** |

用户最怕的"小修改里藏着的关键决策"，就是后两行：**物理极小、重要性极高**。所以判定维度只能是重要性。

## 二、判定三问（任一"是" = 决策）

1. **广连带** —— 它会牵动其他步骤 / 文件 / 参数吗？
2. **不可逆** —— 后续是否都基于它？撤回来代价大吗？
3. **推翻旧约** —— 它推翻了已锁定的东西吗？

**三问全否 → 改动。**

边界模糊时**问一句**，不猜。理由：决策漏记的代价（换上下文就丢、方向悄悄漂移）远大于多记一条。

## 三、软信号（不擅自定性，一定打断问）

| 信号 | 表现 | 动作 |
|---|---|---|
| **强调** | "这个一定要…" "特别注意…" | 问："我理解这算一个关键决策，记进档案？" |
| **反复纠结** | 同一个点来回改三次 | 问："要不要把取舍理由记下来，免得后面又绕回来？" |

硬信号（三问）AI 自己判；软信号**必须问**。

## 四、两类记录的差异

| | 决策 | 改动 |
|---|---|---|
| 命令 | `sp.py decision --trigger ① --text "..."` | `sp.py change --text "..."` |
| 文件 | `.spec-pact/decisions.md` | `.spec-pact/changes.md` |
| 时机 | **即时**（同一轮必须落盘） | 可攒批，步骤收尾时一起记 |
| 内容 | 结论 + **为什么** + 触发器 + 轮次 + 步骤 | 只记"改了什么"（diff 摘要） |
| 副作用 | 挂 `pending_sync` 提醒同步主文档 §决策索引 | 无 |

## 五、触发器编号（写进 decisions.md，方便回查）

| # | 触发器 | 判定问题 |
|---|---|---|
| ① | 广连带 | 会牵动其他部分吗？（尤其基础参数） |
| ② | 不可逆 | 做了之后后续都基于它、难回头吗？ |
| ③ | 岔路口 | 这是多选一的方向决策吗？ |
| ④ | 推翻旧约 | 推翻之前已锁定的假设 / 决策吗？ |
| ⑤ | 改边界 | 产物的范围 / 受众 / 目标变了吗？ |

`⑥强调` `⑦反复纠结` 属于软信号，不直接落盘 —— **先问，用户确认后才按决策记**。

## 六、可见性回环

```
AI 识别 → 写 decisions.md → 状态头/回复里点明"已记决策 D-03"
                                    ↓
                         用户看到后裁决
                        ┌────────┴────────┐
                    "不用记"            "还得补一条"
                        ↓                  ↓
              追加 [DOWNGRADED] 标记    补记新决策
              （不删除，保留审计链）
```

- **降级不删除**：在 `decisions.md` 原条目追加 `[DOWNGRADED → 改动] 理由 + 时间`。
- 最终裁决权始终在用户手上；AI 的职责是**先亮出来**，而不是替用户决定什么重要。

## 七、反模式

- ❌ 把每次措辞调整都记成决策 → 噪音淹没重点
- ❌ 把"砍掉一个模块"记成改动 → 半年后没人知道为什么少了一半
- ❌ 状态头说"已记录"但没真写盘 → 协议失职，比不记更糟
